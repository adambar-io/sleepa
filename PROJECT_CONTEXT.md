# sleepa (formerly "Roster View") — Project Context

A single-file local web app for viewing a Sleeper fantasy football roster with clearer stats/projections and a local (non-syncing) lineup planner. Built iteratively in Claude chat; handing off to Claude Code from here.

**Give Claude Code both this file and `index.html`** — this file explains the *why* and the gotchas; the HTML file is the current, working implementation.

## What it does today

- Looks up a Sleeper username → resolves to `user_id` → lists their leagues → loads one league's roster
- Shows starters (in the league's real slot order) and bench, each with photo, position, team, injury status
- Position-based color accents (QB blue, RB green, WR gold, TE purple, K grey, DEF cyan)
- Projected points for the current week, computed against **the league's own `scoring_settings`** (not a generic PPR/standard default — this matters for leagues with custom scoring)
- Season-total key stats shown inline per position (e.g. RBs show rush yd/TD/rec, WRs show rec/yd/TD/targets) — no dropdown, always visible
- Click any player → large focus panel: big photo/name, proj/last-game/season-avg/season-total, full raw stat breakdown, and swap candidates for that slot: the slot's current occupant (pinned on top, labeled "Starting", no swap button) plus **bench players only** who are eligible for the slot (including FLEX-type slots), sorted by projection. Other starters are deliberately excluded even if eligible. Clicking a bench player targets the lowest-projected slot they're eligible for
- **Empty starting slots** are tappable (`data-empty-slot`, red row with a ＋ in place of the photo, "Tap to add RB/WR/TE"): `openEmptySlot(i)` opens the same panel/sheet with the bench players eligible for that slot (`groupForSlot`, so FLEX / SUPER_FLEX etc. work), best projection first, each with **Add** (`swapIntoSlot`). No eligible bench player → a "Find one on Waivers" button pre-filtered to that position (FLEX for multi-position flex slots). `ctx.focus = {kind:'empty', slot}`. `ctx.originalStarters` is padded with `'0'` to the number of starting slots so an empty trailing slot still gets a row. Empty slots count in the alert banner ("Fill it" button, `data-fix-slot`), the Lineup badge, and pane mode's default pick (bye starter → empty slot → first starter)
- **Optimal lineup** (✦ button in the Starters header; `runOptimal` → `optimalStarters` → `pickFlex`; rule-based since Sept 2026, replacing an exact Hungarian solve so FLEX follows PPR preferences): (1) **locked** players — their team has kicked off this week (`isLocked`, kickoffs from nflverse.json `kick`) — stay in the slot Sleeper has them in, and locked bench players can't come in; (2) the pool skips Out / IR / Doubtful / PUP / Sus (`OPT_SKIP`, using `effectiveStatus`), byes, Sleeper `reserve`/`taxi`, and anyone with no projection — Questionable is fine; (3) **dedicated slots** (QB, RB, WR, TE, K, DEF, IDP) get the top-projected players at the position; (4) **flex slots** last from who's left, most restrictive first (fewest eligible positions, e.g. WRRB_FLEX before FLEX before SUPER_FLEX). In a flex, a WR wins unless an RB projects ≥ `FLEX_PREFERENCE.RB_OVER_WR` (1.0) more than the best WR, or a TE ≥ `FLEX_PREFERENCE.TE_OVER_WR_RB` (1.5) more than the best WR or RB; other positions a flex allows (QB, IDP) compete on projection alone. Margins live in `FLEX_PREFERENCE` (one place). Chosen players already in one of their slots keep it (`place`), so no pointless WR1/WR2 swaps. The note shows Sleeper total → new total (real projections), **Undo**, and an explanation list: "FLEX: chose WR X over RB Y, 0.6-pt difference (RBs need +1.0)", a warning when a **TE is in a flex**, which locked players were left in place, and a notice if kickoff times aren't loaded. Rows get a **Locked** chip once the game starts and a **TE in FLEX** chip (amber) whenever a tight end sits in a flex slot — manual swaps included. `pickFlex` was unit-checked on the margin edge cases (exactly +1.0 wins; float tolerance 1e-9)
- **Checks page** (`tests/check.html`, open it over http(s), e.g. the Pages URL + /tests/check.html): pulls the real functions out of index.html by name (quote-aware brace matching; renaming one of these functions breaks the page loudly) and runs 37 checks: `calcPoints` vs Sleeper's live `pts_ppr` for the last completed week, `pickFlex` margin edge cases (reads the current `FLEX_PREFERENCE`), `statDirection` and `h2hCompare` (lower-is-better, ties at display precision, missing values), and that every live injury status is in `INJURY_STATUS`. Player cards for every chooser list come from one builder, `candCardHTML(pid, {acts, current, open})`
- **Negative air-yards share** (`airPct`): nflverse values go below zero (down to -39%) when targets are mostly behind the line; shown as "<0%" with an explanatory tooltip in the waiver rows, player page game log, full-screen waivers and head-to-head. **Head-to-head across positions**: a stat only one player records shows "—" (not 0), so it is neither colored nor counted in "Better in N"; same-position comparisons still treat an unrecorded counting stat as 0
- **Failure handling**: `fetchLeagueBundle` uses `allSettled` and names the part that failed (league settings / rosters / league members / current NFL week); `setError(msg, retry)` adds a **Try again** button that re-runs the step. User lookup separates "no such user" (Sleeper returns null) from "couldn't reach Sleeper". A first-visit player-list failure (players.json and Sleeper both down) says so. Failed projections no longer pass silently as a 0.0 total: the Updated line shows "Projections didn't load · tap to retry" (`ctx.projFailed`). The season comes from Sleeper `state/nfl` (month-based guess only as a fallback). No silent `catch(e){}` left. Each case was tested by failing that request in the test harness (`?fail=user|rosters|users|league|state|players|projections`)
- **Slot eligibility** (`fantasyPositions`, `canFill`, `eligibleSlotIndexes`, `posInGroup`): uses Sleeper's `fantasy_positions`, falling back to `position`. Needed for IDP leagues: positions are DE/DT/CB/S but slots are DL/LB/DB, so before this a DE or CB could never fill a DL/DB slot; 184 players on teams have two fantasy positions (e.g. LB+DL), none of them QB/RB/WR/TE (live data, Sept 2026). Used by the optimizer, swap panel, empty-slot panel, player page and the waiver FLEX comparison
- **Storage hygiene** (`lsSet`, `pruneStatsCache`): per-player season-stats caches (`sleeper_stats_v2_player_<id>_<season>`) are pruned after each league load to the newest `STATS_CACHE_MAX` (150) for the current season; other seasons are removed. Writes go through `lsSet`, which on a quota error evicts the oldest half of the stats caches and retries once (tested with a simulated 5 MB iOS-style quota). Failed writes are logged, not swallowed
- **Light mode palette** (Sept 2026): warm "stone and paper" instead of stark white: page `#E8E5DE`, cards `#F4F2EC` (no pure white), warm charcoal text `#23221F`, accents a shade deeper than dark mode (green `#18814E`, red `#C4321F`, amber `#A2670F`) and warm-tinted shadows. iOS status-bar color (`THEME_BG.light` + the light theme-color meta) matches `--bg`
- **Playoff seeding check** (`checkSeeding`): for a non-default `playoff_seed_type`, the app replays the league's previous finished season (rosters + winners bracket, 3 requests, cached in `rv-seedcheck:*`) with the wins → ties → PF order and says whether it matched Sleeper's real bracket. For the owner's league ("Last Minute League", seed type 1) the 2025 season matched exactly (teams, byes, round-1 pairs); another seed-type-1 league did not, hence the per-league check
- **Add/drop threshold**: a swap is only suggested when it gains at least `AD_MIN_GAIN` (15) rest-of-season points or 8% of the bench player's value; smaller gaps say "no clear upgrade"
- **Saved draft lineup** (`saveDraft` on every lineup render, `restoreDraft` on load; localStorage `rv-draft:<leagueId>` = {week, season, sleeper, draft}): your planned changes survive closing the app. Cleared, with a note, when the week changes, when your actual Sleeper lineup differs from the one you planned against, or when the league's slots change; a background refresh applies the same rule (`applyLeagueBundle` → `ctx.draftNote`). Players no longer on your roster become empty slots. Restoring shows "Welcome back: your planned lineup (N changes) is still here"
- **Remembered login** (`rememberLogin`, `autoOpen`; localStorage `rv-last` = {username, leagueId}): after the first load the app opens straight to that team (setup form hidden, "Opening your team…"), including falling back to last season's league list; switching leagues updates it; Settings → "Use a different Sleeper account" forgets it. Failures fall back to the setup screen with a retry
- **Trade helper** (League tab button, or tap a team in the standings; full-screen `trade`; `tradeHTML`, `tradeResult`, `bestLineupTotal`, `weekProj`): pick a team, tick players on each side. Two valuations side by side: **Rest-of-season points** (sum of each side's ros.json points in league scoring, starters or not) and **Lineup impact** (for each remaining week, my best starting lineup with vs without the trade, summed, plus per week and playoff weeks). Each week's lineup comes from `fillLineup`, the same core Optimal Lineup uses (dedicated slots, then flex with the WR/RB/TE preference). This week uses real projections; future weeks use each player's average projected week, zero in weeks without a projection (ros.json `k` lists the projected weeks, so byes and injury weeks drop out). Week-by-week diverging bars; playoff weeks marked. Labeled an estimate: no roster limits, waivers or the other team's side. Checked on the owner's league: getting a player never lowers any week, giving one away never raises any week, byes show as dips
  - **Layout (Sept 2026)**: a side-by-side summary at the top (`.tr-side`): **my team left, theirs right**, "You send" / "They send", each side's players as compact cells (position · name · rest-of-season points) paired row by row so the **ROS totals sit on the same line** under each side; tapping a cell opens the player page. Then the two result cards, week-by-week, note, and the two rosters to pick from, also side by side on iPhone (was stacked). Phone rows (≤560 px): last name only (`tradeName`: full name on wider screens), position, ROS, injury as a colored dot, no checkbox (selected = green outline), no team/bye line; tap a row to add/remove, the `›` button next to it (`.tr-info`, `data-open`) opens full details. Class names avoid the existing `.tr-row` (standings list) and `.opp` styles: `.tp-row`, `.ts-head.them`.
- **Build resilience**: `get()` retries 5xx/timeouts (3s/6s/12s). Target/air share, snap counts and depth charts are optional: if a download fails, the previous nflverse.json values are carried forward and listed in `stale` (tested by breaking the snap-count URL: 811/811 values kept), instead of failing the whole build
- **Players tab** (was Waivers; internal view id still `fa`; `renderPlayers`, `plList`, state `ctx.pl`): three views sharing one toolbar: **Available** (free agents), **Trending** (Sleeper most added / dropped, 24 h, top 50), **All players** (every QB/RB/WR/TE/K/DEF on an NFL team or a roster, owner shown). Tools: multi-select positions (`All` clears; `FLEX` toggles RB+WR+TE), name search (accent/punctuation-insensitive, debounced, updates only the list so the iPhone keyboard stays up), sort (projection / trending order, rest of season, season avg, snap, target, air share, games), and stat filters (`PL_METRICS`: presets + custom ≥/≤ builder; percentages typed as 20 = 20%; a player without the stat never passes) shown as removable chips with **Clear all**. All state persists across views. **Sortable columns**: tap Player / Snap / Tgt / Proj in the list header (wide layouts) or Player / Snap by week / Tgt share / Air share / Proj in the full view to sort by it; tap again to flip ascending/descending (`setSort`, `ctx.pl.dir`; players without the stat always sort last); phones use the Sort menu plus a ↑/↓ button. The **full view** has the same position chips, active filter/search chips and Show more, all shared with the tab (`posChipsHTML`, `togglePos`). Target/air share show "—" for QB/K/DEF instead of 0%. Pipeline pool → positions → search → filters → sort, pools built once per data load and sorted by projection (`plMemo`, reset by `plReset` on load/refresh); 25 rows per page (opening ~17 ms, switching ~9 ms on the owner's real league). Rows: free agents show "vs your weakest" (or FLEX), others show the owner / "On your team"; tap opens the free-agent panel, your player's panel or the player page. `ctx.faPos` is derived (`syncFaPos`: ALL / FLEX / single / MULTI) for older code (add/drop, FLEX comparison, full view). Add/drop shows in Available when positions are selected
- **weekly.json** (build, from the same Sleeper weekly stats as `dvp`; replaced season.json in Sept 2026): every QB/RB/WR/TE/K/DEF player's stats for each **completed game**, `{season, generated, through_week, players: {sid: {"<week>": {t: team, o: opponent, s: stats}}}}` (~200 KB / 28 KB gzipped after 2 weeks; about 14 KB gzipped per week). Only games actually played (Sleeper `gp > 0`). Kept: counting stats, bonus buckets, `_lng`; dropped: Sleeper's own `pts_std/ppr/half_ppr/idp`, ranks/ADP, `gp/gs/gms_active`, team snap counts, per-attempt rates (`WEEKLY_DROP`). The app loads it at start (IndexedDB copy for first paint, re-checked with a cheap conditional request on every refresh) and builds every player's scored game list from it (`hist(pid)`, memoized, reset by `histReset`). Completed weeks newer than `through_week` (the Action runs a few times a day) come straight from Sleeper's weekly stats (`fillGapWeeks` → `ctx.gapWeeks`, at most the last 3 weeks). My roster still uses the per-player download (`getPlayerSeasonHistory`, cached daily), which is also the fallback for anyone when weekly.json is missing (`ensureHistory`)
- **Waiver value (Oct 4 2026)**: a fourth Players-tab view (`data-pl-view="value"`, `renderWaiverValue`, container `#wv`; `#fa-view.pl-value` hides the list, search, sort and filters, while the position chips stay and filter the adds). `bestLineup(players, rosterPositions, scoringSettings, week)` returns `{ week, total, slots: [{ slot, pid, pts }] }`: the single-position slots are solved together exactly (`assignDedicated`), then the flex slots, narrowest first (WRRB before FLEX before SUPER_FLEX; IDP_FLEX after DL/LB/DB), each take the best remaining player. It is pure projection, with no WR/RB/TE preference and no locks. Points come from `lineupPts`: Sleeper's weekly projection × the league's scoring (`projPoints`, first downs corrected), and 0 on a bye, for anyone ruled out this week (`cantPlay`) or with no projection. `waiverValue()` (memoized in `plMemo.wv`, cleared by `plReset`) computes:
  - Marginal value of each free agent = L(roster + p) − L(roster).
  - Drop cost of each of mine = L(roster) − L(roster − p).
  - IR / taxi players are left out of the pool and the drop list. A free agent whose game has kicked off is skipped this week.
  - Swaps (`swapFor`, top 8 adds): for each add, the drop that loses least, computed exactly as L(roster − d + a) − L(roster), because the two moves can interact. With an open roster spot (roster_positions minus IR/TAXI, compared with active players) no drop is needed.
  - Shows the best 5 swaps, then the top 8 adds next to the 8 cheapest drops (ties sorted by lowest projection).
  - **Rest of season (Oct 5 2026)**: a This week / Rest of season toggle (`ctx.wvMode`, `rv-wv-mode`). `lineupPts(pid, week, sc)` takes this week from the weekly projections; for later weeks it uses ros.json: the player's average projected week (`projPoints(r.s) / r.w`) in the weeks listed in `r.k`, zero otherwise. `waiverWeeks('ros')` = this week through `ros.through_week`. The values assume today's roster all season, so a backup QB shows up as bye or injury cover.
  - **Exact speed-ups**: in week w, an add who projects no more than the weakest player in my best lineup (and no slot is empty) can't raise it, and a player outside that week's best lineup costs nothing to drop, so those weeks are skipped. Checked against brute-force sums in BATTLEBALL weeks 4–17: 714 lineups matched, 25/25 adds, every drop and swap matched, and 0 of 142 random free agents left out were missed. It takes about 0.8 s in an IDP league and is memoized.
  - `bestLineup(…, opts)`: `opts.pts(pid)` overrides the points, and `opts.fixed` pre-places players (aligned with the non-bench slots). The **trade helper** now uses it (`bestLineupTotal`), so its lineup impact is pure points instead of Optimal Lineup's WR/RB/TE flex preference. Optimal Lineup itself still uses `fillLineup` + `pickFlex`.
- **Lineup check in Sleepa Zone (Oct 5 2026)** (`zLineupCheck`, `zLcHTML`, `[data-lc]` in each card and grid tile): my Sleeper lineup vs `bestLineup` with that league's slots, scoring and Zone projections (`zProj`).
  - A starter whose game has started is locked in his slot (`opts.fixed`), and a locked bench player can't come in. Ruled-out starters (`cantPlay`), byes and empty slots score zero and are flagged.
  - It shows "✓ Best lineup set", or "9.25 below your best lineup · Bye: R. Rice", with Start / Sit names; gaps under `LC_MIN` (0.05) are ignored. Nothing is shown once every starter is locked.
  - The header shows "N lineups to fix" (`data-zn-lcgo`: goes to the first such league, focusing it in the grid) or "Lineups set ✓". There is a guide entry too.
  - Verified on week 5 for all three leagues: best totals matched a brute-force optimum exactly.
  - **Verified (Oct 4 2026)**: `bestLineup` totals matched a brute-force exact optimum (Hungarian over every slot × player) in 228 cases in The League (PPR, 2 FLEX) and 236 cases in BATTLEBALL (IDP, incl. LB/DL dual-eligibles): roster, roster + each of the top 60 free agents, roster − each player, and 150 random pools. waiverValue runs in ~100–150 ms.
- **"vs your weakest"** ignores players in IR/taxi spots and anyone not startable (it used to compare against IR players)
- **Add / drop** (`renderAddDrop`, top of Waivers, follows the position filter; FLEX = RB/WR/TE): my 2 lowest-value bench players at the position next to the 3 best available. Value = rest-of-season points from ros.json in league scoring (`rosValue`; byes count as zero, so a good player on bye this week isn't flagged); each also shows last-3 vs season average (`recentTrend`, needs 3 games) and floor/ceiling. A one-line verdict when the best available beats the weakest bench by more than 5 points. Free agents' histories are fetched on demand for the trend
- **Trending** (`renderTrending`): Sleeper's official `/players/nfl/trending/add|drop?lookback_hours=24&limit=25`, cached 30 min; Most added / Most dropped, add/drop counts, projection, position, and a badge (Available / Yours / Rostered) from the league's rosters; "Available only" filter; tap opens the free-agent panel, your player, or the player page
- **Floor / ceiling** (`weekRange`): typical bad / good week from this season's league-scored games. 6+ games: 20th/80th percentile; 3-5: lowest/highest, marked early (italic); under 3: not shown ("needs 3+ games"). Rows show "8–19" under the projection; the player page shows a bar (bad week · projection · good week); head-to-head has two rows. Early in the season (2 games) it is intentionally absent everywhere
- **Matchup difficulty** (`dvpInfo`, `dvpChipHTML`): points the opponent's defense allowed to the player's position (QB/RB/WR/TE/K), per game, scored with the league's settings from nflverse.json `dvp`; ranked 1-32 and labeled "3rd-most to WRs" / "5th-fewest to TEs" (green top 8, red bottom 8). Under `DVP_MIN_GAMES` (4) games it is grey, outlined and says "· 2 gms"; the tooltip / player-page sentence says rankings will move. Shown on lineup, bench, waiver and opponent rows, the player page and head-to-head
- **Late-game flex** (end of `optimalStarters`): after the picks, each flex slot swaps with a dedicated-slot starter who kicks off later, when both players fit both slots and neither is locked. Same players, same total; the note says who moved and both kickoff times
- **Bye-week planner** (`byePlan`, below the bench): the next `PLAN_WEEKS` (4) weeks; a player is out for a week if their team is on bye or their current Sleeper status is not startable. Dedicated slots are filled first (single-position players first), then flex; any unfillable slot is flagged with who is out at that position
- **Matchup card** (`matchupCardHTML`, `myMatchup`, top of Lineup and League): this week's opponent from Sleeper `/league/{id}/matchups/{week}` (fetched on load and refresh; failures just hide the card), both projected totals with the same league-scored projections, and when your plan differs from Sleeper both your plan total and your Sleeper-lineup total with each margin. Tap ("Compare lineups") → **side-by-side matchup** (full-screen `opp`, `oppHTML`): my lineup (my plan, or the Sleeper lineup if unchanged) and my opponent's Sleeper lineup slot by slot, the higher projection in each slot green and the lower red (`h2hCompare`), totals and "you win N of M slots", holes called out for both teams (`lineupHoles`: empty, bye, not startable), both benches collapsed; tapping a player opens their page. On phones photos are hidden and names wrap to two lines
- **League tab** (`renderLeague`): matchup card + standings (record, PF, PA) with the playoff line after `settings.playoff_teams` and regular-season weeks left (`playoff_week_start - 1`, counting this week). Order = wins, ties, points for, which reproduced real 2025 Sleeper brackets for `playoff_seed_type` 0 (with and without divisions: playoff teams, byes and round-1 pairings). A 2025 league with seed type 1 did NOT follow that order, so other seed types get a visible warning; divisions get a note (division-winner guarantees unconfirmed). No playoff odds
- **Build data for new features**: nflverse.json `dvp` = raw stats each defense allowed per position (QB/RB/WR/TE/K) summed over completed weeks + games (`build_dvp`, from Sleeper weekly stats with `opponent`), and **ros.json** = each player's projected raw stats summed from the current week through week 17 (`build_ros`; bye weeks have empty projections so they add nothing; ~30 KB gz). Both are raw so the app scores them with the league's settings (scoring is linear)
- **Injury statuses** (`INJURY_STATUS`, `statusInfo`, `cantPlay`): one table for every status Sleeper uses (checked against live /players/nfl, Sept 2026: Questionable, Doubtful, Out, IR, PUP, Sus, NA, COV, DNR). It drives the chips (label, short form, tone: warn / doubt / out), the optimizer's can't-start rule, the Playing card and callouts. Only Questionable is startable; unknown future values show as-is and count as startable
- **Data freshness** (`refreshData`, "data freshness" block near the top of the script): cached data paints immediately and is replaced in the background. Per type (US Eastern, where the NFL week runs): rosters / lineup / league / users / NFL state / projections are fetched on **every open or return to the app**; the **player database** (it carries injury status) is re-downloaded on game days (Thu/Sun/Mon until 3am the next morning) on every open, at most every 15 min, otherwise once a day and again after each game day (`isStale('players')`); **season stats** once a day and after each game day (`isStale('daily')`, per-player cache timestamps); **nflverse.json** is re-checked on every open (`fetchNflverse`, `cache: 'no-cache'` so an unchanged file is a cheap 304) — the IndexedDB copy is only a first-paint placeholder, never a season-long cache. Triggers: `visibilitychange` → visible, `pageshow` with `persisted` (iPhone restoring from memory), window `focus`, `online` — throttled to once a minute — plus a 30 s ticker that refreshes every 15 min on game days (hourly otherwise) while the app is open, and the manual **↻ Updated N min ago** button under the page title (every view; "Updating…" while running, "Couldn't update · tap to retry" if Sleeper fails; manual = re-download everything). Settings / sidebar status lists when each type was last updated. A refresh keeps your plan: if the draft equals the Sleeper lineup it follows Sleeper's new lineup; if you've made changes they stay (anyone no longer on your roster becomes an empty slot); a new week or a changed slot layout starts over from Sleeper (`applyLeagueBundle`). A failed projections call (empty result) keeps the previous projections. `applyNfl` only moves forward (compares `generated`), so a slow cached read can't overwrite a fresher download. The game-day clock (`etInfo`, `lastGameDayEnd`) uses `Intl` with `America/New_York` and was checked across EDT/EST
- **Upcoming game line** (`gameLineHTML`, player detail screen, under the position/team line): one compact line, "Wk 3 vs ARI · Sun, Sep 27, 4:05 PM EDT" (vs = home, @ = away), or "BYE — Week 5 · Next: Wk 6 vs LAC · …" (`nextGame` looks ahead to the next scheduled week). "· kicked off" once the time has passed. Omitted when nflverse.json isn't loaded or the player has no team.
  - **Source**: nflverse schedule `https://github.com/nflverse/nflverse-data/releases/download/schedules/games.csv.gz` (one row per game: season, week, gameday, gametime, home_team, away_team), built into nflverse.json by the Action (browsers can't fetch GitHub release files: no CORS). Only this source is used for schedule info (no Sleeper/ESPN comparison).
  - **Fields**: `sched[team][week]` = "vs OPP" / "@ OPP" (a missing week = bye, `sched_weeks` = last week); `kick[team][week]` = kickoff in UTC. `gametime` is US Eastern (checked against known kickoffs: Thursday 8:15 PM ET = 00:15Z, Thanksgiving night in EST); `eastern_to_utc` converts DST-aware; the app shows it in the device's time zone via `toLocaleString` (checked: 4:05 PM EDT = 1:05 PM PDT = 21:05 BST).
  - **Team → game**: the player's Sleeper `team` (nflverse `LA` mapped to `LAR`) looked up in `sched`/`kick` for the current week; current week = Sleeper `state/nfl` (`ctx.week`), the same as everywhere else.
  - **Caching**: part of nflverse.json (IndexedDB copy for first paint, re-checked with a cheap conditional request on each open; the Action rebuilds it a few times a day), so schedule changes like flex moves arrive within hours.
- **Injury reports, three sources side by side** (`injurySourcesHTML` on the player detail screen, `injuryMiniHTML` one line per source in the panel/sheet): shown when any source has an injury status (Sleeper `injury_status`, nflverse game status, or ESPN status other than "Active"). Each source is its own subsection with its own "as of", every field it provides, and "No data from this source" (or "… unavailable") when empty. **Never merged for display.** Decisions (Optimal Lineup, Playing card, chips) still use `effectiveStatus`: this week's official nflverse game status if any, else Sleeper; ESPN is display-only (owner's choice, Sept 2026)
  - **Sleeper**: players.json (the Action's trimmed copy of `https://api.sleeper.app/v1/players/nfl`, fields `PLAYER_FIELDS` incl. injury_status, injury_body_part, injury_notes, injury_start_date, practice_participation, practice_description, espn_id). Refreshed every 30 min on game days / daily otherwise (owner chose this over a daily direct 14.7 MB fetch). "as of" = when the app last loaded it
  - **nflverse**: `injuries_{season}.csv` (release tag `injuries`), built into nflverse.json `inj` by the Action: raw `st` (report_status), `ri/ri2` (report injuries), `pi/pi2` (practice injuries), `ps` (latest practice status), `p` (by-day log), `g` (game date). Join: gsis_id → Sleeper via the same ID map as the rest of nflverse.json. Rows on this week's report for QB/RB/WR/TE/K that don't match are listed in `inj_unmatched`. The file has no report dates; "as of" = the release asset's update time (`inj_as_of`)

## Architecture

One HTML file (vanilla JS, no build step, no framework), inline CSS, Google Fonts (Inter) loaded via `<link>`. No backend — Sleeper's API is called directly from the browser. The one companion is **`nflverse.json`**, a static data file built by **`build_nflverse.py`** and served next to the HTML (see "nflverse" below for why it can't be fetched from the browser directly).

Files:
- `index.html` — the app (was `sleeper-roster-view.html` until Sept 2026)
- `build_nflverse.py` — Python 3, standard library only. `python build_nflverse.py [--season 2026]` → writes `nflverse.json` (~50 KB in week 3). Skips rewriting if only the timestamp would change
- `nflverse.json` — generated; commit/deploy it alongside the HTML
- `.github/workflows/update-nflverse.yml` — daily GitHub Action (14:00 UTC + manual "Run workflow" button) that re-runs the script and commits the JSON as `github-actions[bot]`

**Hosting (live since Sept 23, 2026):** GitHub Pages from `adambar-io/sleepa` (repo renamed from `roster-view` on Sept 23, 2026), branch `main`, root. App: https://adambar-io.github.io/sleepa/ (the HTML is `index.html`). GitHub Pages does **not** redirect after a repo rename, so the old `/roster-view/…` URLs 404. Verified end to end: the Action's bot commit automatically triggers a "pages build and deployment" run, so the refreshed `nflverse.json` goes live with no manual step. Uploading through GitHub's web drag-and-drop **skips the `.github` folder** — the workflow file had to be created with "Add file → Create new file". Scheduled Actions are paused by GitHub after 60 days of no repo activity (likely in the off-season); re-enable from the Actions tab.

## Data sources

### Official, documented API (`api.sleeper.app/v1/...`)
Stable, safe to rely on:
- `/user/<username>` → user_id
- `/user/<user_id>/leagues/nfl/<season>` → leagues
- `/league/<league_id>`, `/rosters`, `/users` → league/roster/owner data
- `/players/nfl` → full player dictionary (14.7 MB raw / 2.6 MB gzipped). **Only a fallback now**: the GitHub Action writes a trimmed **players.json** (same data, `PLAYER_FIELDS` only incl. `fantasy_positions` and injury fields; 1.57 MB raw / ~260 KB gzipped, all 12k players) next to nflverse.json and rebuilds it every 30 min on game days. The app fetches players.json (`downloadPlayers`, `cache: no-cache` so unchanged = 304) and falls back to Sleeper only if it is missing/broken; the heavy fallback refreshes daily, players.json follows the game-day rule. Cache: localStorage `sleeper_players_cache_v4` with `source`
- `/state/nfl` → current NFL week

### Images (Sleeper CDN, all via `playerImageUrl`)
- Players: `https://sleepercdn.com/content/nfl/players/<player_id>.jpg`
- Team defenses have no headshot at that path (their "player_id" is the team abbreviation), so they use the team logo: `https://sleepercdn.com/images/team_logos/nfl/<team lowercase>.png`. Verified all 32 teams load. Like the headshots, this is an unofficial CDN path

### Unofficial/undocumented endpoints (`api.sleeper.app/...`, no `/v1/`)
**Not documented by Sleeper, no uptime/shape guarantee, could change without notice.** Reverse-engineered from community write-ups. Two gotchas that already bit us once — don't reintroduce them:
1. `season_type` is a **query parameter** (`?season_type=regular`), never a URL path segment
2. Projections come back as a **JSON array** of per-player entries (not an object keyed by player_id); the per-player history endpoint is the opposite — see Gotcha #3 below. Both are normalized

Endpoints in use:
- Projections (current week, bulk): `GET /projections/nfl/<season>/<week>?season_type=regular&position[]=QB&position[]=RB&position[]=WR&position[]=TE&position[]=K&position[]=DEF`
- Season history (one call per roster player — much cheaper than looping the bulk endpoint per week): `GET /stats/nfl/player/<player_id>?season_type=regular&season=<season>&grouping=week` → array of that player's weekly actuals for the season

Both are normalized client-side: raw stat categories may come back nested under `.stats` or flat on the entry — the code checks `entry.stats || entry` and filters to `typeof === 'number'` before summing, since flat responses can include string metadata fields (team, opponent, date) that would otherwise get concatenated into the totals.

**Gotcha #3 (fixed Sept 2026):** the season-history endpoint actually returns an **object keyed by week** (`{"1": {...}, "2": {...}, "3": null, …}`), not an array — projections *are* an array. The old array-only parser silently produced empty histories for every real player (Last gm / season stats all "—"). `normalizeHistory` accepts both shapes; the cache prefix was bumped to `sleeper_stats_v2_` to drop the cached empties. Each week's entry also carries `opponent`, `is_away_team`, and rich stats including `off_snp` / `tm_off_snp` (snap counts) and `rec_air_yd`, plus Sleeper's generic `pts_*` and `pos_rank_*` fields (excluded from stat displays).

### nflverse (via `build_nflverse.py` → `nflverse.json`)
**Why a build script:** nflverse data lives in GitHub *release assets*. Browsers can't fetch them — `github.com/.../releases/download/...` redirects to a storage host without CORS headers ("Failed to fetch"), and the GitHub API asset route fails the same way (and is capped at 60 req/hour unauthenticated). Verified Sept 2026. The depth-chart file is also 52 MB (194 daily snapshots), far too big for a phone.

Sources (all `https://github.com/nflverse/nflverse-data/releases/download/<tag>/<file>`, `.csv.gz` versions):

**Gotcha:** the older `player_stats` release stopped updating in May 2025 — use `stats_player`. Target share lives in the weekly player stats, not Next Gen Stats.

**Kickoffs (`kick`):** `{team: {week: 'YYYY-MM-DDTHH:MM:00Z'}}` from the schedule's `gameday` + `gametime` (ET, converted with `eastern_to_utc`, DST-aware); drives locking in the optimizer.

**Injuries (`inj` in nflverse.json, Sept 2026):** nflverse `injuries/injuries_{season}.csv` has **one row per player-week** holding the latest practice status and the official game status — no dates, so no by-day history on its own. The build keeps each team's **upcoming** game (schedule `gameday`, first game on/after today ET) and, for Sleeper-matched QB/RB/WR/TE/K on that week's report, writes `{w, g (game date), st (Questionable/Doubtful/Out), b (injury), p: {date: DNP|LP|FP}}`. The by-day log is built across builds: each run files the current status under the practice day it belongs to — the latest of the team's three report days (`practice_days`: game −4/−3/−2, or −3/−2/−1 for Thursday/Saturday games) whose ~4pm ET report was out before nflverse last updated the file (release asset `updated_at` via the GitHub API; `inj_as_of`) — and carries forward the days from the previous nflverse.json for the same week. A day nflverse never updated in shows "No report". The Action runs at 14:00, 23:30 and 03:30 UTC so each day's report is caught when nflverse has it; `us_eastern()` converts without tzdata. Mirrored in the app by `practiceDays()`.

**Join (done in the script, output keyed by Sleeper ID):** for every Sleeper QB/RB/WR/TE on a team: (1) dynastyprocess `sleeper_id→gsis_id`, (2) Sleeper's own `gsis_id` (only ~20% populated and some have stray spaces — hence last resort), (3) unique normalized name + team match against nflverse `players`. Sept 2026 result: 828 players → 741 / 3 / 64 matched, **20 unmatched** (fringe rookies/practice squad). Snap counts are keyed by PFR id, mapped via `players.pfr_id` + dynastyprocess `pfr_id`. Team abbreviations: nflverse `LA` → Sleeper `LAR` (`TEAM_FIX`).

**`nflverse.json` shape:** `{season, generated, stats_through_week, depth_as_of, sched_weeks, sched: {TEAM: {"<week>": "vs KC"|"@ KC"}}, players: {<sleeper_id>: {d: "WR1", w: {"<week>": {s: snap%, t: tgt share, a: air share}}, sh: "sh_…" (stathead.app key), nfl: "<NFL.com slug>", nflt: "<team it was verified for>"}}, nfl_team_slugs: {TEAM: "kansas-city-chiefs"}, nfl_unresolved: [<sleeper_id>], coverage}` (plus kick, inj, dvp and the others described above). Every matched player has an entry (possibly `{}`), so a **missing key = no ID match**; the app logs roster and free-agent match counts to the console (`logNflCoverage`).

**In the app:** `loadNflverse` fetches `nflverse.json` (relative URL) in parallel with the roster load and re-renders when it arrives — it never blocks. Cached in **IndexedDB** (`roster-view` DB, `kv` store, key `nflverse`) only as a first-paint placeholder: the file is re-checked on every open (see Data freshness); the cached copy is used if that fails. Sleeper caches stay in localStorage. If the file is missing/blocked/wrong season → console warning, `ctx.nfl = null`, all nflverse values show "—"; roster, projections, lineup builder, waiver list and Analysis work normally (verified with the fetch blocked and cache cleared). Must be served over http(s) — `file://` can't fetch it.

### Deliberately not used
- **FantasyPros official API — owner's free key tested Sept 28 2026 (probe run 36443909293): data is REAL and current** (weekly RB = fantasypros.com incl. rank_min/max/ave/std; ROS too; projections real) **but every response is capped at 10 rows** (`"tier": "free", "public_api_limited": true, "limit": 10`, no paging documented), `position=ALL` is rejected by consensus-rankings (one call per position), and `tier` comes back null. So the free key isn't used; the mirror stays the source. A paid HOF key would need a re-probe. Earlier notes — terms (PDF at api.fantasypros.com/public/v2/terms-of-use, read Sept 2026): 1 call/s, **100 calls/day**, personal non-commercial use only, no redistribution, non-compete, attribution required, no historical stats. The **free key returns sample data** (pricing page / FAQ: real personal keys come with a HOF subscription). `fantasypros_probe.py` + the manual "FantasyPros probe" workflow (secret `FANTASYPROS_API_KEY`, ≤10 calls, writes nothing) are ready to test a key; the plan is to use it only for last-minute Sunday updates on top of the free mirror below. Docs findings: consensus rankings = ECR / pos rank / tier; spread only via `/rankings?range=true&rankstats=true`; projections are raw stat lines (no scoring param); FantasyPros `sportsdata_id` = Sleeper `sportradar_id`.
- **nflverse Next Gen Stats / PFR advanced stats** — not needed for the current signals
- **Pro Football Reference** — no public API; would require scraping, which is against their ToS. Not used, not recommended.

## Scoring math

Every points value (`Proj`, `Last Gm`, `Season Avg`, `Season Total`) is computed client-side via `calcPoints(rawStats, scoringSettings)`, which multiplies each raw stat category the league's `scoring_settings` actually knows about. This means the numbers reflect this specific league's rules, not Sleeper's generic `pts_ppr`/`pts_std` fields.

## Known limitations / open issues
- **Practice by day depends on nflverse's update timing.** If nflverse doesn't refresh its injuries file between two report days, the earlier day shows "No report" (its status was overwritten before a build saw it). The log only starts from when this shipped (Sept 23, 2026)
- **Cold start still asks for the username**: freshness covers reopening/resuming a loaded app; the setup screen doesn't remember the last user/league

- **No write-back to Sleeper.** The lineup builder is purely local planning — there's no public API to submit a lineup change. Options discussed but not built: (a) browser automation to fill Sleeper's own UI, (b) a browser extension overlaying Sleeper's site so real form submissions still go through Sleeper, (c) reverse-engineering Sleeper's authenticated internal write endpoints (needs session cookie, higher risk of breaking).
- **nflverse data is only as fresh as the last `build_nflverse.py` run.** nflverse itself updates stats/snaps the day after games and depth charts several times a day. Without the GitHub Action, re-run the script weekly (e.g. Tuesday).
- **~2–3% of skill players have no nflverse match** (mostly fringe rookies); they show "—". The console lists which roster players are missing.
- **Bye rows / opponent use the player's *current* team**, so a mid-season trade can mislabel earlier weeks in the game log (Sleeper's own per-game `opponent` is used for played weeks, so only BYE rows are affected).
- **Season share averages are the mean of weekly shares**, not total targets ÷ total team targets (team totals aren't in the JSON). Close, but not identical.
- **Team defense (`DEF`) history**: verified the per-player history endpoint works for team IDs (e.g. `BAL`). DEF/K get no nflverse signals besides opponent/bye.
- **Season averages** are total ÷ weeks with a Sleeper stat entry. Byes have no entry (null weeks are dropped), so they don't drag the average down; a week where the player was inactive but has an entry would.
- **Undocumented endpoints are the biggest fragility risk.** If projections/season-stats suddenly show "—" everywhere again, check the browser console first (warnings are logged when a response parses to 0 players) before assuming the whole architecture is broken — it's usually a shape or URL-structure mismatch, not total endpoint removal.
